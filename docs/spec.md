# キャンプギア管理アプリ（Flutter）仕様書 v1

Nov 21, 2026 · @まんどぅ

## 概要と決定事項

持っているキャンプギアを家族で共有し、登録したギアから毎回の持ち物チェックリストを作れるアプリ。キャンプのたびに開く理由があるので、登録して終わりにならない。

| 項目 | 決定内容 |
| --- | --- |
| 想定ユーザー | 自分と家族。オートキャンプ中心 |
| 言語 | Flutter（iOSとAndroidの両方に出せる） |
| ギアの記録項目 | 写真・ブランド・購入日・スペック・収納場所・使用場所・感想 |
| 共有 | 家族で共有する（v1から入れる） |
| 保存先 | Firebase（データはFirestore、写真はCloud Storage） |
| 広告 | 下部バナー ＋ 持ち物チェック完了時の全画面広告 |

## 写真とデータの保存先

データはFirestore、写真はCloud Storage for Firebaseに置く。写真を圧縮すれば、個人アプリの規模ではほぼ無料枠に収まる。

**なぜFirebaseか**

- **電波の弱いキャンプ場でも使える**：Firestoreはオフラインでも読み書きでき、つながったときに自動で同期する。チェックリストを現地で使うこのアプリでは、これが一番大きい。
- **共有がリアルタイム**：家族がチェックしたら、自分の画面にもすぐ反映される。
- **ログインが標準である**：Apple・Googleでのログインがすぐ使える。
- **Flutter公式のパッケージがある**（FlutterFire）。
- LaravelでAPIを作る案もあるが、オフライン同期を自分で作る必要があり、サーバー代も毎月かかるので見送る。

**費用の目安**

- Cloud Storageは2026年2月から従量課金のBlazeプランが必須になった。ただし無料枠は残っている（[Firebase公式FAQ](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024)）。クレジットカードの登録が要るので、予算アラートを月100円などに設定しておく。
- 写真はアップロード前に長辺1280px・約300KBに圧縮する。ギア200個×写真2枚で約120MBで、無料枠（5GB）なら40世帯前後まで入る。
- それを超えた分は1GBあたり月数円。広告収入の方が先に大きくなる見込み。
- 一度表示した写真は端末にキャッシュし、ダウンロード量を抑える。

## データ構造

すべてのデータを「家族」の下にぶら下げる。共有の権限を家族単位の1か所で判定でき、セキュリティルールが単純になるから。「使用場所・感想」はギアに直接書かず、キャンプ記録に紐づける。そうすると「このテントをどこで何回使ったか」が自然にたまる。

| データ | Firestoreの場所 | 主な項目 |
| --- | --- | --- |
| 家族 | `households/{id}` | 名前、メンバー、招待コード |
| ギア | `households/{id}/gears` | 名前、カテゴリ、ブランド、購入日、スペック（サイズ・重量・容量を自由項目で）、収納場所、写真、メモ、状態（使用可・要修理） |
| キャンプ記録 | `households/{id}/trips` | 日付、キャンプ場名、天気、全体の感想 |
| 持ち物リスト | `trips/{tripId}/items` | ギアへの参照（または食材などの自由入力）、チェック済みか、誰がチェックしたか |
| ギアの使用メモ | `trips/{tripId}/items` 内 | 使ったか、その回の感想 |
| テンプレート | `households/{id}/templates` | 名前（「夏・家族2泊」など）、ギアの一覧 |

カテゴリの初期値：テント・タープ / 寝具 / テーブル・チェア / 調理・食器 / 火器・燃料 / 照明 / その他

## 画面構成

下部のタブバーで3画面を行き来する。キャンプ前に一番使う「次のキャンプ」を左端に置く。

1. **キャンプ**（ホーム）
   - 上：次のキャンプの日付・場所と、持ち物の進捗（例：32/40）
   - 下：過去のキャンプ記録の一覧
   - 「新しいキャンプ」で日付・場所を入れ、テンプレートか前回のリストを選んで持ち物リストを作る
2. **持ち物リスト**（キャンプを開いた画面）
   - カテゴリごとのチェックリスト。タップでチェック、誰がチェックしたかを小さく表示
   - ギア以外の「食材」「氷」なども自由に追加できる
   - 帰宅後に「使った・感想」を入れると、ギアの使用履歴に残る
3. **ギア**
   - カテゴリで絞れる写真付きの一覧。収納場所での絞り込みもできる
   - 詳細画面：全項目と、このギアを使ったキャンプの一覧（場所・感想）
4. **設定**（右上から）：家族の招待・メンバー管理、テンプレートの編集、ログアウト、アカウント削除

バナー広告はタブバーのすぐ上に置く。

## 家族共有とログインの仕組み

最初に使った人が「家族」を作り、招待コードを家族に送って参加してもらう。参加した人は全員、ギアもリストも同じように編集できる。

1. 初回起動でAppleかGoogleでログインする
2. 「家族を作る」か「招待コードで参加する」を選ぶ
3. 招待コードは6文字、24時間で失効。LINEなどで送れるようにシェアボタンを付ける
4. 参加すると、家族のメンバー一覧に自分が追加される

- **なぜAppleログインも必要か**：iOSでGoogleなど外部のログインを使う場合、App Storeのルールで同等のプライバシー配慮をしたログインの選択肢も求められる。Appleでサインインを入れておくのが確実。
- **権限の判定**：Firestoreのセキュリティルールで「ログイン中のユーザーがその家族のメンバーか」だけを見る。写真のStorageも同じ考え方。
- **同時編集**：後から保存した方が勝つ。チェックのオン・オフは項目ごとに保存するので、家族で手分けしてチェックしても衝突しない。
- v1では1人1家族まで。友人グループなど複数参加は後で広げる。

## 広告

常に表示するのはタブバー上のバナー1つ。全画面広告は「持ち物を全部チェックし終えた」区切りで、キャンプ1回につき1回だけ出す。

| 広告 | 場所・タイミング | ルール |
| --- | --- | --- |
| バナー | タブバーのすぐ上 | チェックを押し間違えないよう、リストとは余白を取る |
| 全画面 | 持ち物が全部チェックされ、「準備完了」画面を閉じたとき | 同じキャンプでは1回だけ。最初のキャンプでは出さない |

- **なぜチェック完了時か**：作業が終わった自然な区切りで、邪魔に感じにくい。出発前の焦っているときに割り込むと不満になる。
- 家族で手分けしているときは、最後の1つをチェックした人にだけ出す。
- テスト広告ID、トラッキング許可、プライバシーの申告は他の2アプリと共通。Flutterでは`google_mobile_ads`パッケージを使う。
- Androidも出すので、Google Playのデータセーフティ欄への記入も必要。

## 実装ステップ（Claude Code用）

開発中はFirebase Local Emulator Suiteを使い、自分のMac上でFirestore・認証・Storageを動かす。課金も本番データも気にせず試せ、セキュリティルールのテストも書けるため。

1. **プロジェクト作成**：Flutterプロジェクトを作り、状態管理はRiverpod、画面遷移はgo\_router。一問一答アプリと構成をそろえると行き来しやすい。
2. **Firebaseの準備**：Firebaseプロジェクトを作り、`flutterfire configure`で接続。エミュレーターを起動できる状態にする。
3. **ログインと家族**：Apple・Googleログイン、家族の作成、招待コードでの参加。ここでセキュリティルールを書き、テストも付ける。
4. **ギア管理**：一覧・登録・編集・絞り込み。写真は`image_picker`で選び、圧縮してからStorageへ。表示はキャッシュ付き。
5. **キャンプと持ち物リスト**：キャンプ作成、リスト生成（テンプレート・前回から）、チェック。機内モードでオフライン動作を確認する。
6. **使用記録**：帰宅後の「使った・感想」入力と、ギア詳細での履歴表示。
7. **広告**：テストIDでバナーと全画面広告、出すルール。
8. **本番の準備と公開**：Blazeプランへの切り替えと予算アラート、アカウント削除、プライバシーポリシー。家族で実際のキャンプ1回に使ってから審査に出す。
